# Решения и возможности среды

## Реализация плана (2026-10-21)

- Без серверного исходника/подтверждённого update real-редактирование честно unsupported; demo update проверяется тестами. Предлагаемый контракт в README.
- SWR только в памяти, TTL 5 минут централизован в BudgetCache; scope member/household, epochs и commit в одном continuation; никаких новых polling/realtime. Существующая очередь записи не заменяется.
- Предзагрузка соседних месяцев удалена: пользы не измерено, критические summary/list_tx загружаются параллельно. Synthetic доказал dedup, не ускорение wall-clock.

## Сканер чеков (2026-10-22)

- Ключ чека — `fn:i:fp`, сервер считает его сам и проверяет формат; клиентский `receipt` не считается доверенным. Уникальность — partial index `(household_id, receipt_key) where receipt_key is not null and deleted_at is null`, чтобы удалённый чек можно было добавить снова.
- Локальный `ReceiptStore` namespaced по `member.id:household_id`, ограничен 200 записями и хранит связь local/server id. Это защита от дублей до ответа сервера и между перезагрузками; серверная защита остаётся главной.
- `SEND_RECEIPT_KEY` держали `false` до миграции и деплоя API; после применения миграции `20261022073910` и деплоя `api` v13 флаг включён. Серверный `add_tx` добавляет поле `receipt_key` только при наличии ключа, поэтому старый сервер без миграции не ломает обычные записи.
- Фото обрабатывается на устройстве: сначала BarcodeDetector, затем jsQR с ограниченными по времени/размеру попытками. Файл никуда не отправляется. `src/vendor/jsqr.js` версионируется вручную (`?v=1`), лицензия Apache-2.0 рядом.
- Каталог `supabase/` остаётся ignored по существующему правилу; серверные правки лежат локально и не попадают в обычный commit без отдельного решения.

## Модули v1, 2026-11-03

- REST `/v1` живёт внутри существующей функции `api` (`api/v1.ts`, `v1_http.ts`, `v1_validate.ts`, `v1_serialize.ts`, `v1_errors.ts`, `v1_path.ts`); legacy `{initData, action}` не изменён.
- Новые таблицы только аддитивно, `recurring_payments` остаётся источником для старого UI; `api/legacy_sync.ts` синхронизирует шаблон, скрытие и оплату без второго расхода. `due_reminders` пропускает платежи, у которых есть шаблон v1.
- Один движок повторений `_shared/recurrence.ts` для трёх модулей; генерация ограничена окном и идемпотентна (`on conflict`), пропущенные периоды не бэкфиллятся.
- Уведомления — `notification_outbox` с `dedupe_key`, claim через `skip locked`, backoff, отмена при оплате/выполнении/удалении/паузе; 403 → `failed` без ретраев, 429 → `retry_after`. Старые очереди не менялись.
- Задачи: `task_series` (шаблон) + `tasks` (экземпляры), один будущий экземпляр на серию; завершённые чистятся через `delete_after`.
- Валюта — `module_preferences.currency` (по умолчанию `RUB`), снимок в `payment_templates.currency` и `payment_occurrences.currency`; конвертации нет.
- Миграции и деплой из текущей среды возможны через Supabase MCP (`apply_migration`, `deploy_edge_function`). MCP сохраняет относительные пути файлов, поэтому `_shared` не дублируется; миграции применять по одной с паузой ≥1 с из-за версии-таймстампа.
- Подробности модели, rollback и деплоя — `docs/api/BACKEND.md` и `docs/api/DEPLOY_CHECKLIST.md`.

## Память (2026-10-21)

Используем небольшие Markdown-файлы с загрузкой по необходимости. AGENTS обнаруживается Codex штатно; обновление остальных файлов — инструкция агенту, не фоновый сервис. Контрольные точки по этапам нужны из-за отсутствия доступного агенту надёжного счётчика контекста и гарантированного pre-compaction hook. Глобальные настройки оставлены без изменений.

## Аудит среды на 2026-10-21

- Сеанс: Codex desktop, PowerShell/Windows; доступный bundled CLI сообщает `0.163.0-alpha.10.2`. Это версия CLI, версия GUI отдельно не установлена. CLI вывел предупреждения доступа к временным PATH aliases, но версию вернул успешно.
- Глобальный AGENTS пуст; проектных AGENTS/override и `.codex/` до настройки не найдено. Глобальный config: `model = "gpt-6.1-sol"`, reasoning `low`; явных верхнеуровневых context/auto-compact overrides не обнаружено.
- Кэш моделей: gpt-6.1-sol (500000), gpt-6-astra, gpt-6-sol, gpt-6-luna, gpt-5.6-sol/terra/luna (272000). Это метаданные кэша, не гарантия эффективного окна текущего сеанса. Текущие инструменты также перечисляют эти модели и дают субагентов (до 4 активных агентов суммарно). Для этой небольшой настройки делегирование не потребовалось.
- Практическое распределение: gpt-6-luna — рутина; gpt-6.1-sol — обычная разработка; gpt-6-astra — сложная архитектура/отладка. Это роли по доступным описаниям, не подтверждённые цены или гарантия экономии. Выбор вручную, без смены модели во время настройки.
- Штатная автокомпакция поддерживается; `model_auto_compact_token_limit` — порог в токенах, по умолчанию модельный. Не задаём фиксированный порог для всех моделей. У агента этого чата нет инструмента чтения текущего процента или запуска compact. Лимиты аккаунта не равны заполнению контекста.
- Документированы `/status`, `/model`, `/compact`; конкретную доступность проверять в меню `/` установленного клиента. CLI также поддерживает `codex resume`; новый чат восстанавливает смысл работы через файлы памяти, а не полную переписку.

Источники: [настройки](https://learn.chatgpt.com/docs/config-file/config-reference), [штатные команды](https://learn.chatgpt.com/docs/developer-commands?surface=cli), [практика файлов контекста](https://developers.openai.com/cookbook/examples/codex/iterating-development-workflows-with-codex).

Глобальные жесты только в app.js, собственные жесты расходов и sheet сохраняют приоритет. Подробности и ограничения — README, раздел UI/UX v2.
