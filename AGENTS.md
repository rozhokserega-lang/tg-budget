# Работа с контекстом

- При старте прочитай только `.agent/STATE.md` и выполни `git status --short --branch`. После сброса/сжатия или при продолжении незавершённой работы прочитай `.agent/HANDOFF.md`. Если инструкции уже в контексте, не перечитывай их.
- При расхождении памяти и файлов доверься Git и коду; уточни только затронутые сведения. Не повторяй полный аудит.
- `.agent/ARCHITECTURE.md` — карта модулей; `DECISIONS.md` — решения и ограничения среды; `TASKS.md` — очередь. Открывай их по необходимости, не все сразу.
- Перед чтением кода определяй минимальный набор файлов, необходимых для текущей задачи; расширяй его только по мере необходимости. Для небольших задач не создавай отдельный план и не запускай субагентов.
- Сначала `rg -n` по конкретным путям/символам, затем нужный диапазон файла. Не сканируй весь проект и не читай большие файлы/логи целиком без необходимости. Ограничивай вывод; неизменённый уже прочитанный код повторно не загружай без причины. Для проверки изменений используй адресный `git diff`.
- После крупного этапа, смены задачи, перед завершением и перед доступным ручным сжатием сохраняй контрольную точку. Не рассчитывай на предупреждение перед автоматическим сжатием или аварийным закрытием.
- Контрольная точка: в STATE обнови цель, прогресс, блокеры и один следующий шаг; в TASKS — статусы; в HANDOFF — изменённые пути, проверки и нерешённые вопросы передачи. Устойчивое решение записывай только в DECISIONS, карту — только в ARCHITECTURE. Не дублируй содержимое: используй ссылки.
- Не переписывай файлы памяти, если их содержимое фактически не изменилось. После небольших изменений обновляй только те файлы памяти, в которых действительно поменялись сведения; правило контрольной точки не требует перезаписи остальных файлов.
- Ориентиры объёма памяти: STATE и HANDOFF — до 100 строк каждый, DECISIONS — до 200, TASKS и ARCHITECTURE — до 150 каждый. Если компактность конфликтует с сохранением важной информации, сохраняй информацию: эти ориентиры не являются жёсткими лимитами.
- Память должна быть короткой и актуальной: без переписок, сырых логов, кода, секретов и персональных данных. Устаревшее сжимай или удаляй; ценные заменённые решения переноси в `.agent/archive/` только при необходимости, архив на старте не читай. Не создавай дополнительные документы без причины.
- Субагенты допустимы для объёмного изолированного анализа документов, архитектуры, зависимостей, ошибок/логов, проверки тестов и review. Для простой задачи работай сам. Делегируй ограниченный вопрос; получай краткий вывод, пути/строки, проверки, риски и рекомендации, без сырых файлов. Учитывай суммарную стоимость и запрет конфликтующих правок.
- Если достоверная метрика текущего контекста доступна: при 70% сохрани точку, при 80–85% используй доступное штатное сжатие или предложи новый чат после сохранения. Без метрики не оценивай проценты на глаз: сохраняйся по этапам. Не фиксируй размер окна числом и не имитируй автоматические хуки.
- Модель меняет пользователь штатным выбором. Не меняй глобальную конфигурацию, не подключай API и не делай коммит ради памяти. Кратко описывай результат и проверки, не выводи целые файлы.

Ручные команды пользователю: «Сохрани контрольную точку» — обновить память по правилам выше; «Восстанови контекст и продолжи» — выполнить стартовый порядок и следующий шаг из STATE после сверки с HANDOFF и Git.
