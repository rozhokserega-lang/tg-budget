# Напоминания: контракт адаптера v1 (предложение для Backend-разработчика)

Статус: серверного контракта в checkout нет, согласование ещё требуется.
До подключения `window.APP_REMINDERS_ADAPTER` production показывает состояние недоступности.
В demo автоматически используется memory-only mock; данные исчезают при перезагрузке.
Mock не отправляет уведомлений и не является реализацией сервера.

Подключить адаптер до app.js. Все методы возвращают Promise (или значение для mock).
Аутентификация — существующая Telegram initData на сервере. `scope` используется
клиентом для защиты от устаревших ответов; это НЕ источник авторизации.
Backend определяет владельца по проверенной сессии, проверяет его при каждом методе,
не принимает household_id, ответственных или права на чужие напоминания.
Ошибка — rejected Error с безопасным message (и при необходимости code).
Записи не хранятся в общем финансовом кэше; controller очищает snapshot при смене пользователя.

## Методы

| Метод | Аргумент | Результат |
| --- | --- | --- |
| list | `{scope, from: YYYY-MM-DD, until: YYYY-MM-DD, timezone: IANA}` | `{reminders: Reminder[], occurrences: Occurrence[]}` |
| save | `{scope, reminder: ReminderInput}` | `{ok:true}` |
| remove | `{scope, id}` | `{ok:true}` |
| pause | `{scope, id, paused: boolean}` | `{ok:true}` |
| complete | `{scope, occurrence_id, date, timezone, idempotency_key}` | `{ok:true}` |

`ReminderInput`: `{id?: string, title: string, description: string, date: YYYY-MM-DD,
time: HH:mm, timezone: IANA, priority: 'normal'|'important', repeat: null|Repeat,
notifications: number[]}`. `Reminder` добавляет `id` и `paused:boolean`.
Название 1–160 символов после trim, описание до 4000, дата 1900–2100.
`notifications`: уникальные целые минуты ДО события, 0 = в назначенное время,
пустой массив = без уведомлений, до 10 значений в пределах 0–525600.
Важность влияет только на оформление, не на сортировку/доставку.

`Repeat`: `{unit:'day'|'week'|'month'|'year', interval:1..999, weekdays:number[]}`.
Дни недели ISO: 1 = Пн, 7 = Вс. Непустой weekdays допустим только для week;
недели считаются от понедельника недели исходной даты. Пустой массив означает
день недели исходной даты. События до исходной даты не создаются.
Для month/year сохраняется исходное число: 31 января → 28 февраля → 31 марта;
29 февраля → 28 февраля в невисокосный год → 29 февраля в високосный.
Локальные date/time хранятся вместе с IANA zone; смена зоны устройства не меняет расписание.
DST: неоднозначное время осенью — более ранний instant; несуществующее весной —
сдвиг вперёд на величину перехода. Это предлагаемая политика для согласования с backend.

`Occurrence`: `{id: string, reminder_id: string, date: YYYY-MM-DD, time: HH:mm,
due_at: ISO8601 UTC}`. date/time — проекция instant в запрошенную list timezone.
ID стабилен при повторах запросов; complete адресует конкретное событие, не расписание.
Backend рассчитывает расписание централизованно; production UI не расширяет repeat.
list возвращает ВСЕ незавершённые просроченные события независимо от from,
а также события диапазона from..until, включая определения paused и без событий.
Контракт v1 без пагинации: нельзя молча обрезать события. Для больших выборок нужен
согласованный контракт пагинации перед production-подключением.
UI запрашивает до года вперёд или конца выбранного месяца, если он позже.

## Атомарность и уведомления

- complete идемпотентен по occurrence_id; повторный запрос успешен.
- Разовое: удалить напоминание и отменить оставшиеся задания Telegram доставки.
- Повторяющееся: завершить только occurrence, отменить только его оставшиеся уведомления.
  Следующие события сохраняются. Отдельного пользовательского архива нет.
- Просроченное не завершается автоматически.
- remove удаляет расписание и незавершённые события, отменяет связанные уведомления.
- pause прекращает доставку, сохраняет уже наступившие незавершённые события.
  Пропущенные во время паузы повторяющиеся события не создаются после resume.
  Разовое событие остаётся доступным для ручного выполнения, даже если его дата прошла во время паузы.
  Возобновление не отправляет накопленные уведомления и не сбрасывает якорь repeat.
- save пересчитывает только будущие события, сохраняя уже наступившие незавершённые
  occurrences. Backend обязан разрешать гонки save/complete/pause/delivery транзакционно.

- Сервер сверяет paused/completed непосредственно перед отправкой Telegram сообщения.
- В production не следует включать адаптер до проверки изоляции, повторений,
  DST, pause/resume, дедупликации отправки и отмены уведомлений.

## Проверка в Telegram после подключения

Два пользователя одной семьи не видят записи друг друга. Создать разовое и
повторяющееся событие, несколько уведомлений, отметить одно событие, проверить
оставшееся расписание. Проверить pause/resume после пропуска даты, редактирование,
смену timezone, отказ сети, возврат из background и обновление свайпом вниз.
