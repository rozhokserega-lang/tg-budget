# Развлечения: API и оставшиеся требования

Сверено с main и `backend/leisure/functions/leisure/index.ts` 2026-11-09. В этой ветке сервер и схема не изменяются.

## Существующий API

Endpoint `${APP_LEISURE_API_URL}` либо замена `/api` на `/leisure`.

Все персональные операции: POST JSON `{initData, action, ...payload}`. Backend проверяет Telegram HMAC, срок initData, определяет members по telegram_id. Клиент не передаёт owner_id.

| action | Payload | Результат |
|---|---|---|
| load | — | Snapshot |
| cities | query, минимум 2 символа | cities[] |
| preferences | preferences: city_id, categories[], exclude_visited, radius_km, origin_lat, origin_lon | Snapshot |
| saved | id, favorite?, visited?, planned_on? | Snapshot |

Snapshot содержит preferences, daily.places, saved[{place_id,favorite,visited,planned_on,place}], categories. Существующий saved обеспечивает персональное избранное, повторное открытие, независимое обновление полей. Не заменять его отдельным локальным хранилищем.

GET `/catalog?city_id=…&cursor=…`: `{city_id,data:Place[],nextCursor,license,licenseUrl,attribution}`; до 200 объектов на страницу. Это публичные данные OSM, без персональных полей. Клиент проходит все страницы, проверяет повтор курсора, объединяет по id, кеширует на 5 минут в памяти. Повторные открытия и вкладки не создают лишних запросов. Ошибка любой страницы не подменяется частичным успешным каталогом.

Place: `{id,name,category,city?,address?,description?,lat?,lon?}`. Средний чек, рейтинг, фотографии и точный тип заведений не гарантируются.

## Реально поддерживаемые категории

| Направление | ID |
|---|---|
| Еда | cafe, restaurant |
| Развлечения | cinema, theatre |
| Отдых и прогулки | park, walk |
| Спорт и активность | active |
| Культура | museum, sight |

Кофейни и скверы сейчас объединены с cafe и park. Не выдавать суши, зоопарки или торговые центры за точные фильтры этих широких групп.

Для полного ТЗ требуется расширить нормализацию OSM, импорт и серверную валидацию: кофейни, бары, пиццерии, суши/роллы, фастфуд, кондитерские; боулинг, бильярд, квесты, караоке, концертные площадки, развлекательные центры; скверы, набережные, зоопарки, ботанические сады, аквапарки, аттракционы; спорткомплексы, фитнес, бассейны, катки, батуты, скалодромы, велопрогулки; выставки, галереи, исторические объекты; ТЦ, рынки, книжные магазины. Возвращать capabilities/categories с группой, title и ID. Только достоверные теги OSM; отсутствующий тип не угадывать по названию. Для велопрогулок отдельно определить модель маршрута: текущий Place представляет точку.

## Поиск: текущий вариант и расширение

Сейчас поиск честно выполняется по всем загруженным объектам выбранного города: name, address, description, category и русскому названию категории. Debounce 350 мс, максимум 50 отображаемых результатов с предложением уточнить запрос, очистка, загрузка, ошибка и пустое состояние. Сохранённый радиус применяется по координатам, расстояние по прямой; неизвестные координаты исключаются при активном радиусе. Во вкладке избранного поиск только по сохранённым местам. Смена города/аккаунта защищена счётчиком поколений; отдельные запросы на каждый ввод отсутствуют. Это не семантический поиск: «роллы» и «птицы» найдут только упоминания в имеющихся данных.

Для масштабирования предлагаем POST action `search`, `{query,city_id,category_ids?:[],cursor?:string,limit?:number}`. Origin/radius брать из персональных настроек. Ответ `{places:Place[],nextCursor,capabilities:{supportedCategoryIds:[],fields:[]}}`. Проверять длину query 1–100, limit 1–50, принадлежность cursor исходному запросу; поддержать русскую морфологию и типы OSM без внешнего запроса на каждую букву. Ошибки: VALIDATION_ERROR, UNAUTHORIZED, UNAVAILABLE, UNSUPPORTED_FEATURE; frontend не должен вызывать этот action до согласования и реализации.

## Предпочтения

Город, девять категорий, exclude_visited, точка и radius_km уже сохраняются. Сброс в клиенте возвращает текущий город и начальные категории, убирает точку/радиус; сервер обновляется по «Сохранить настройки».

Предлагаемые дополнительные поля preferences: `budget: free|low|medium|any`, `rest_types: (calm|active|romantic|family|friends|culture)[]`, `extras: {children:boolean,couple:boolean,company:boolean,outdoors:boolean}`. Радиусы UI: 1,3,5,10 км либо null. Новые поля пока показаны отключёнными, не отправляются существующему API и не создают ложное успешное сохранение.

Для использования фильтров Place нужны проверенные атрибуты с происхождением и nullable значениями: price_level, child_friendly, outdoor, rest_types, company_suitable. Не считать null значением false или бесплатным входом. Возвращать supportedPreferenceFields, применённые фильтры и объяснение непроверяемых пожеланий. Не заявлять «подходит детям» на основании одной категории.

## Подборки

Текущий клиент группирует реальный каталог по темам, объединяет с daily/saved без дублей, показывает максимум 5 мест и фактическое количество доступных объектов. Это тематическая группировка по типу, не персональная семантическая рекомендация. Общий каталог содержит только существующие объекты; фиктивного заполнения до трёх нет.

Для полного списка настроений предлагаем action `collections`, `{city_id}` → `{collections:[{id,title,description,symbol,total,places:Place[]}]}`. По 3–5 мест при наличии. Темы: уютный вечер, свидание, активный отдых, природа, друзья, семья, культура, недорого. Нужны достоверные данные для семьи и бюджета; до их появления не обещать соответствие. Учитывать сохранённые категории, точку/радиус, exclude_visited и поддерживаемые пожелания. Стабильные ID, дедупликация, кеш по member/city/revision/day. Изменение saved не должно менять daily snapshot.

## Изоляция и проверки

Сохранить HMAC Telegram, ограничение возраста initData, независимость пользователя от payload. GET catalog не должен раскрывать initData, координаты пользователя, saved или preferences. Серверное избранное уникально по (owner,place), операции идемпотентны; пользователь A не читает и не изменяет данные B. Не открывать service_role браузеру. Проверить два аккаунта, два устройства, повтор saved, снятие favorite без удаления planned_on, просроченную подпись, ошибки сети, отсутствующие атрибуты и импорт категорий.

Блокеры полного ТЗ: детальные категории, расширенные предпочтения, семантический поиск, дополнительные достоверные темы подборок. Новые таблицы/Edge Functions требуют отдельного согласования. Frontend и эта ветка их не создают.
