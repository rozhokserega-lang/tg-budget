# Личный трекер задач: граница интеграции

Согласованный серверный контракт в репозитории отсутствует. Новые HTTP endpoints не придуманы и действующие контракты не изменены. Production показывает состояние ожидания. Для подключения внедрить `window.APP_TASKS_ADAPTER` до `app.js`, реализующий нижеописанный интерфейс. Это контракт frontend-адаптера для обсуждения с backend, а не утверждённый HTTP API.

Все методы возвращают Promise. Все аргументы содержат `scope` — полный `member.id:household.id`, без удаления member.id. Scope служит защитой UI; backend обязан определять пользователя по проверенному Telegram initData, проверять владельца каждого списка/задачи и никогда не доверять scope из клиента.

| Метод | Остальные аргументы | Результат |
| --- | --- | --- |
| list | — | `{lists, tasks, preferences}` — полный личный снимок |
| saveList | `id: string|null, name` | произвольный JSON |
| removeList | `id` | произвольный JSON |
| save | `task, idempotency_key` | произвольный JSON |
| complete | `id, idempotency_key` | произвольный JSON |
| restore | `id, idempotency_key` | произвольный JSON |
| remove | `id` | произвольный JSON |
| preferences | `selected?`, `sort?`, `view?, order?: string[]` | произвольный JSON |

Список: `{id, name}`. Задача: `{id, title, description, list_id: string|null, due_on: YYYY-MM-DD|null, priority: normal|important, repeat: null|{unit: day|week|month|year, interval: 1..365, weekdays: number[]}, reminders: number[], created_at: ISO, completed_at: ISO|null, delete_after: ISO|null}`. В save нового объекта id отсутствует. Дни недели: ISO 1=Пн…7=Вс, только для недельного повторения; пустой массив означает повтор в исходный день недели. Напоминания: уникальные целые минуты 0..525600 до начала дня срока в часовом поясе профиля, максимум 10. Эта семантика требует согласования с общим API уведомлений перед подключением.

Настройки `{selected: 'all'|'none'|listId, sort: 'due'|'priority'|'created'|'manual', orders: {[view]: taskId[]}}` сохраняются на сервере на пользователя. Независимый порядок для каждого представления. Перемещение задачи между списками — save с изменённым list_id; порядки остальных представлений сохраняются, новые для представления задачи попадают в конец. Удаление списка атомарно обнуляет list_id у активных и выполненных задач и переводит выбранный удалённый список в none.

complete должен атомарно установить completed_at/delete_after (+30 дней), отменить ожидающие уведомления и создать ровно один следующий экземпляр. Повторный complete того же экземпляра, в том числе после restore, не создаёт второй следующий экземпляр. Хранить связь экземпляров/уникальность на сервере, а не только request key. Месячные/годовые повторы сохраняют исходный день с ограничением до последнего дня месяца; выбранные дни недели учитывают N-недельный интервал от недели срока. Следующий срок берётся от расписания, не от времени выполнения. restore сохраняет все поля, обнуляет completed_at/delete_after и восстанавливает подходящие будущие уведомления; уже созданный следующий экземпляр сохраняется.

Сервер самостоятельно удаляет выполненные через 30 дней и запрещает позднее восстановление. Клиент не запускает очистку. Удаление активной задачи также отменяет её уведомления. API должен дедуплицировать создание по idempotency_key (ключ формы сохраняется при повторной отправке после неизвестного сетевого результата). Методы удаления и настройки идемпотентны.

Mock только в demo, в памяти, изолирован по полному scope. Эмулирует атомарность/повторы и настройки, но не Telegram-уведомления и серверную очистку. Production не переходит на mock при ошибках. Существующий BudgetCache используется для загрузки, сброса после изменений и защиты устаревших ответов. UI применяет изменения после подтверждения сервера, без риска неоправданного оптимистичного удаления.

Проверить после подключения: два пользователя одной семьи; уведомления и timezone/DST; таймаут после успешной мутации и повтор запроса; серверный purge/восстановление до/после 30 дней; повторяющиеся задачи после восстановления и повторного выполнения; Telegram touch drag, BackButton, pull-to-refresh и возврат в приложение.
